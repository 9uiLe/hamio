# hamio 実装設計

hamio は [API v1](api.md) の要求を受け、入力検証、状態管理、端末表示、JSON 応答を一つのプロセスで処理する。業務処理を実行する仕組みは持たない。本書は内部の責務とデータの寿命を定め、製品の品質条件は[基本設計](design.md)、ビルドと検査の操作は[開発手順](development.md)に定める。

## モジュールと依存方向

| モジュール                            | 責務                                                          |
| ------------------------------------- | ------------------------------------------------------------- |
| [contract.ts](../src/contract.ts)     | 実装版、API 版、資源上限、型、安定したエラー                  |
| [validation.ts](../src/validation.ts) | 未知の JSON を検証済みの要求モデルへ変換する                  |
| [form.ts](../src/form.ts)             | 提供値・既定値の検証と、成功・不足・無効値の判定              |
| [session.ts](../src/session.ts)       | run / task の状態遷移、保持上限、最終集計                     |
| [io.ts](../src/io.ts)                 | 上限付き UTF-8 入力、NDJSON の切り出し、期限付き出力          |
| [prompts.ts](../src/prompts.ts)       | フォームを Clack へ変換し、キー入力・秘密入力・端末復旧を扱う |
| [display.ts](../src/display.ts)       | 秘密値の除去、安全な文字列表示、表、通知、進捗の描画          |
| [cli.ts](../src/cli.ts)               | オプション、モード、入出力経路、キャンセル、終了コードの統合  |

契約、フォーム判定、状態遷移は端末ライブラリに依存しない。検証は `unknown` から始め、閉じたキー集合と種別ごとの型を確認する。CLI と描画は検証済みモデルを受け取り、独自の要求解釈を重ねない。I/O のない規則は、端末や子プロセスなしで検証できる。

CLI が各モジュールを接続し、モードに応じて描画を選ぶ。Clack のアダプターは対話モードで動的に読み込む。依存の都合による型と設定は内部に閉じ、公開 JSON へ漏らさない。

## フォームの処理

1. CLI オプションと端末条件を確認し、定義ファイルと提供値を上限付きで読む。
2. JSON の構造、フォームの項目、既定値を検証する。
3. 提供値を優先して既定値を解決し、無効値と必須の不足項目を求める。
4. 無効値があれば質問せず返す。非対話なら成功または不足を返す。
5. 対話では不足項目を一つずつ質問し、回答を同じ項目制約で検証する。
6. 全回答が確定したら stdout へ一つの JSON を返す。中断時は部分回答を破棄する。

Clack 1.8.1 を端末アダプターとして使う。custom input/output と AbortSignal を用い、stdin をキー入力、stderr を画面、stdout を回答へ分離する。[Clack 公式文書](https://bomb.sh/docs/clack/packages/prompts/)

質問ごとに入力とキャンセルを管理し、質問を同時に開かない。キー入力は1質問16 KiB、描画の待ち行列は256 KiBまでとする。質問間では出力を排出し、次の質問と前の描画が混ざることを防ぐ。

秘密入力は画面に実値を復唱せず、成功応答の values へだけ含める。SIGINT、SIGTERM、対話中の EOF と Ctrl-C を中断として扱い、listener、raw mode、カーソルを復旧する。

## 表示と秘密値の除去

単発表示では定義全体を検証した後、表示部品を処理する。JSON 応答は正規化した部品と、秘密値を除去したデータから生成する。人向け表示にも同じ秘密指定を適用する。自由文と任意の結果データの秘密指定は利用側が管理する。

外部文字列は端末命令を取り除き、残る制御文字と双方向制御文字を無害化する。表示幅の計算に `Bun.stringWidth`、文字の分割に `Intl.Segmenter` を使い、長い表示を省略する。表は20行まで描画して省略件数を示す。機械向けの非秘密値は、表示幅や端末の都合で変更しない。

画面の装飾は共通の描画モジュールが生成する。端末へ書く内容と JSON で返す値の経路を分け、入力文字列に含まれる ANSI 命令をそのまま端末で実行しない。

## 連続表示の状態と寿命

入力を一件ずつ切り出し、event の構造、runId、seq、task の状態を検証して適用する。最初の `run.start` から一つの Session を使い、`run.finish` で集計と業務結果を返す。完了通知より前の EOF はプロトコル違反とする。

| 状態                           | 保持期間                              |
| ------------------------------ | ------------------------------------- |
| run ID と直前の seq            | run の終了まで                        |
| 活動中 task のラベル・最新進捗 | task.finish まで                      |
| 使用済み task ID               | run 終了まで。最大10,000件            |
| 成功・失敗 task の件数         | run 終了まで                          |
| warning / error 通知           | 最終応答まで。合計100件               |
| info / success 通知            | 表示・任意の event 応答が完了するまで |
| 描画対象の進捗文字列           | 最新値に置き換え、次の描画に使う      |

既定の機械出力は最終応答のみとし、入力の進捗を応答へ複製しない。`--events` 指定時は検証済み event を順に返し、出力が追いつかない場合は背圧を受ける。重要通知の保持上限を超えた場合はエラーにし、古い警告を捨てない。

人向け進捗は一つの保留中の書き込みと最新状態で管理し、最大10 fpsに制限する。通知と結果は進捗行を消してから書く。変化がない間は描画 timer を動かさない。CPU の並列化に Worker は使わず、業務と資源を共有する。

## I/O と失敗の処理

単発 JSON は256 KiB、NDJSON は1行64 KiBを上限として、バイト列を逐次読む。UTF-8 の境界をまたぐ読み取りを扱い、構文解析後も階層、文字列、キー、ノード数、種別固有の件数を検証する。具体的な値は [API 契約](api.md#資源上限と機能照会)に集約する。

出力は書き込み完了を待ち、エラーと5秒の期限を扱う。閉じた pipe や遅い出力を無期限に待たない。CLI は契約エラーを安定した code と終了コードへ変換し、内部例外の stack や入力内容を応答へ含めない。出力障害でエラー JSON 自体を送れない場合は終了コード7を返す。

プロセスの AbortController を中断の入口にし、入力と端末アダプターへ伝える。成功・失敗のどちらでも、進捗描画、signal listener、標準入力、出力の後始末を行う。業務の子プロセスを停止する責務は利用側に残す。

## ランタイムと実行ファイル

[flake.nix](../flake.nix) は開発用ツールと同梱用ランタイムを同じ Nix 入力で固定する。開発用 Bun は Nixpkgs のパッケージを使う。同梱用 Bun は Nixpkgs の `bun.src` が版・SHA-256 を指定する公式アーカイブを展開し、Nix 向け loader 修正を加えずに使う。

Nix shell は同梱用の実行ファイルを `HAMIO_BUN_RUNTIME` に設定する。[build.ts](../scripts/build.ts) はこれを `compile.executablePath` へ渡し、`src/cli.ts` を入口として本体と製品依存を bundle する。ランタイムの自動ダウンロードをビルド中に発生させない。[Bun の実行ファイル仕様](https://bun.com/docs/bundler/executables)

| ビルド項目   | 設定                                                                          |
| ------------ | ----------------------------------------------------------------------------- |
| 出力         | `dist/hamio`。ビルドしたホストの OS・CPU 向け                                 |
| 最適化       | minify 有効。bytecode と smol は使用しない                                    |
| 暗黙設定     | `.env`、`bunfig.toml`、`package.json`、`tsconfig.json` の自動読み込みを無効化 |
| 依存取得     | `--no-install`。実行時の外部 import と取得機構を設けない                      |
| 製品依存     | `@clack/prompts` を含む依存を `bun.lock` の版・integrity で固定               |
| 開発専用依存 | Lint、format、型検査、hooks、画像生成ツールを製品へ含めない                   |

Bun の `BUN_OPTIONS` と `BUN_BE_BUN` はアプリの入口より前に作用するため、起動元の環境を信頼境界に含める。実行ファイルは sandbox ではなく、通常の OS 標準ライブラリも必要とする。

ローカルのビルドスクリプトは実行ファイルを生成する。署名、provenance、SBOM、公開資産の検証と配布は[リリースの受け入れ条件](design.md#12-リリースの受け入れ条件)を満たす別の工程とする。

## 検証の構成

| 層               | 利用側から確認する振る舞い                                                               |
| ---------------- | ---------------------------------------------------------------------------------------- |
| 契約と状態       | 無効な定義、提供値、既定値、順序違反、状態遷移、保持上限                                 |
| CLI プロセス     | stdout / stderr、終了コード、UTF-8、EOF、秘密の非表示、機械出力量、遅い・閉じた出力      |
| PTY              | 入力5種、日本語、選択、秘密、キャンセル、貼り付け上限、端末の復旧                        |
| 同梱実行ファイル | Bun が PATH にない環境、暗黙設定のある作業ディレクトリ、実際のフォームと利用側スクリプト |
| プレビュー       | 製品入口を通した入力・進捗・結果の画像と操作録画                                         |
| 性能             | 配布候補を新規起動した経過時間、CPU、maxRSS、出力量                                      |

契約・CLI・PTY の試験は [api.test.ts](../tests/api.test.ts)、ビルドと単体実行の試験は [executable.test.ts](../tests/executable.test.ts) に置く。性能は [benchmark-api.ts](../scripts/benchmark-api.ts) で別に測定する。試験の実装、OS ごとの実行結果、正式な動作保証は分けて記録する。
