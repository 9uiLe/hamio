# Phase 8 — HTML Renderer implementation

The production HTML renderer reads the same [PresentationState](domain-model.md) as the [Terminal renderer](phase-7-terminal.md). [Design Direction](../design/direction.md), [Tokens](../design/tokens.md), and [Components](../design/components.md) define its appearance and semantic roles. `src/renderers/html.ts` owns pure State → document conversion; `html-style.ts` owns media realization; `html-announcements.ts` derives live announcement candidates from successive accepted States. None of these modules decodes Events, reduces State, reads the environment, or imports Terminal code. The old `html-diagnostic.ts` was removed. The Catalog resolves each shared scenario once and passes that State to both production renderers.

## Representation and boundaries

- Report is the default: a self-contained, initially static document with no JavaScript, remote font, image, CSS, analytics, or runtime resource. Live mode permits one Run-level ongoing cue and, when no Run cue exists, one standalone indeterminate Progress cue. Terminal states do not loop. The document contains empty polite and assertive live regions; `htmlAnnouncement(previous, next)` decides which accepted State changes merit a single announcement. It omits routine Progress updates. The future live transport/DOM update adapter must coalesce snapshots and populate these regions without accepting Events directly or moving focus. Phase 9 decides the public entry point; Phase 10 decides report distribution.
- The live motion pause checkbox affects only representation. It never stops a Run, Event acceptance, or State reduction. Report and reduced-motion conditions use a static, text-labelled indeterminate progress track because Chrome's native indeterminate `<progress>` continued animating under reduced motion even after author CSS animations were disabled. Determinate Progress uses native `<progress>` and always shows `current / total`. This is an implementation-based refinement of the Phase 6 native-first preference, not a Domain change.
- Failure code and human message remain visible outside native `<details>`. Live mode starts optional structured details open and permits native disclosure. Report mode leaves details expanded without a disclosure control, so printing cannot omit them because a user closed a section.
- The renderer emits known markup only and escapes every Presentation string and attribute value. User content is bidi-isolated in its own element so direction controls cannot reorder adjacent status cues. It validates render options at runtime, including document language. The default document language is `en` because generated labels are English. A caller may explicitly provide a different BCP 47 language tag; content language is not guessed from text. Raw secrets do not enter the State. No arbitrary HTML extension or sanitizer is present. A restrictive CSP blocks scripts and external resources while allowing the self-contained style block.
- TaskGroup has only grouping; ContentItems remain siblings in semantic order; Run Result is not inferred from Task results. `none`, `indeterminate`, `0 / total`, `total / total`, JSON null, empty string, no data, redacted, and source truncation remain distinct. Table, Code, and Diff preserve horizontal access. The renderer does not calculate a diff, syntax highlighting, or Task ownership.

## Performance and dependencies

On macOS arm64 with Bun 1.4.2, after five warmups per input, 200 normal and 30 large synchronous renders were timed with `performance.now()`. The normal `task-running-partial` median was about 0.0015 ms, output 12,410 bytes. A 1,050 Task State (1,000 completed, 50 active) plus a 200×12 Table had a median about 0.52 ms, output 429,028 bytes. A depth-16 Tree with long Code and 200 Diff lines had a median about 0.021 ms, output 34,040 bytes over 100 samples. These are local absolute measurements, not a browser update benchmark or a performance guarantee. No content was omitted for speed.

No new dependency or package was added. Native HTML/CSS, CSS custom properties, media queries, and a small escape function cover the requirement; a framework, icon library, animation library, sanitizer, syntax highlighter, and diff engine were avoided. `package.json` and `bun.lock` are unchanged. The HTML renderer and Catalog remain outside the current native executable release artifact. Browser-specific behavior beyond this Chrome/macOS review and actual VoiceOver speech remains unverified.
