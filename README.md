# hamio

hamio は、開発用スクリプトの入力フォーム、進捗、表、結果を統一するターミナル UI ツールです。Shell、Python、Go、TypeScript などから CLI と JSON で呼び出せます。

利用側のスクリプトが業務処理を実行し、hamio が質問の表示、回答の検証、状態と結果の表示を担当します。業務の順序、並列数、権限、再試行は利用側で管理します。本体・製品依存・Bun を含む単一実行ファイルとして配布するため、UI の利用に Bun・Node.js・Nix の導入は不要です。

## 提供状況

公開リリースはありません。利用を試す場合は[ソースからビルド](#ソースからビルドする)し、同じ OS・CPU の別リポジトリへ実行ファイルを配置できます。

| 対象           | 実装・検証の範囲                                                                                              |
| -------------- | ------------------------------------------------------------------------------------------------------------- |
| API v1         | フォーム、単発表示、連続表示、機能照会を実装                                                                  |
| ローカル実行   | macOS arm64 で契約、PTY、同梱実行ファイル、別ディレクトリへの導入と Bun なしの実行を確認                      |
| 配布・更新     | インストーラー、利用側の GitHub Action、Release workflow を実装。導入の失敗処理は GitHub CLI の代替実装で検証 |
| 公開資産の検証 | GitHub の実際の証明検証と Linux の実行結果は未確認                                                            |
| 品質評価       | 性能測定は記録したソース・環境に限定。最低 OS、実端末、アクセシビリティ、全性能予算は配布対象ごとの評価が必要 |

設計上の受け入れ条件は[基本設計](docs/design.md#12-リリースの受け入れ条件)、検査の種類は[実装設計](docs/implementation.md#10-検証の構成)に記載しています。

## スクリプトとの接続

| コマンド       | 用途                                                   |
| -------------- | ------------------------------------------------------ |
| `form`         | 文字入力、確認、単一選択、複数選択、秘密入力を受け取る |
| `render`       | メッセージ、値の一覧、表、進捗、結果、エラーを表示する |
| `stream`       | 改行区切りの JSON から業務の進捗と結果を表示する       |
| `capabilities` | 契約版、製品版、対応機能、資源上限を照会する           |

人向け UI は標準エラー出力（stderr）、回答と機械向けの結果は標準出力（stdout）へ出します。対話フォームの回答も JSON なので、スクリプトが捕捉して業務処理に使えます。利用側の言語ランタイムは利用側で用意します。

AI エージェントと CI は `form --interactive never`、`render / stream --format json` を指定します。対話待ちと装飾を使わず、連続表示は既定で最終結果だけを返します。コマンド、JSON、終了コードは [API v1](docs/api.md)、フォームと表示の例は [examples/](examples/)を参照してください。

## ソースからビルドする

開発とビルドには、`nix-command` と `flakes` が有効な Nix を使います。hamio のリポジトリ直下で実行してください。

```sh
./scripts/dev.sh bun run setup
./scripts/dev.sh bun run build
./dist/hamio capabilities
sh examples/form.sh
```

`setup` は固定した依存を取得し、この clone に Git hooks を導入します。`build` はホストの OS・CPU 向けに `dist/hamio` を生成します。別リポジトリへの配置は[ローカルビルドの利用手順](docs/distribution.md#手元でビルドした実行ファイル)を参照してください。

## 公開版の導入と更新

配布対象は macOS arm64 と Linux x64/arm64 の glibc 環境です。Release workflow は macOS 15 と Ubuntu 24.04 でビルド・実行試験を行います。

利用側は `.hamio-version` に完全な版を記録し、検証済みのインストーラーで `.tools/bin/hamio` へ配置します。インストーラーは GitHub Releases の資産・由来・hash を検証し、成功後に使用する版を切り替えます。更新とロールバックにも同じ検証経路を使います。

導入・更新時には GitHub CLI と通信が必要です。通常実行は配置した実行ファイルを直接呼び出し、通信や自己更新を行いません。[配布手順](docs/distribution.md)にインストーラーの取得・検証、GitHub Actions、版の固定と更新をまとめています。

## 開発とレビュー

日常の作業は `nix develop` で行います。shell 外からは次のコマンドで固定した環境を呼び出せます。

```sh
./scripts/dev.sh bun run format
./scripts/dev.sh bun run check
```

編集時の診断、Git hooks、PR の CI で Lint、format、型、テスト、プレビュー照合を検査します。詳しい検査範囲と性能測定は[開発手順](docs/development.md)を参照してください。

UI やプレビューの生成元を変更した場合は `./scripts/preview.sh` で PNG を生成して目視確認します。操作途中は `./scripts/preview.sh --recording` の GIF で確認できます。[プレビュー一覧](docs/previews/README.md)の `product` は製品 UI、`fixture` は録画基盤の検証用です。
